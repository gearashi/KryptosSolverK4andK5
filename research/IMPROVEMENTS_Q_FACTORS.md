# Q31–Q61: finite factor algorithms and measured guidance

These are bounded methods for a declared integer-product objective. They do not discover Kryptos's unknown method or authenticate a plaintext. Existing defaults remain unchanged. A mathematically correct alternative is not automatically a search-efficiency improvement.

The implementation uses the existing lazy-product schema. Real cipher requests reach the same code through `optimize-plus`: `decomposition` accepts `and_or`, `junction`, `diagram`, `chain`, and `cutset`; `ordering` accepts `strong` and `separator`; `elimination_bound` accepts `overlap`, `adaptive`, `cycles`, `reparameterization`, `mod2`, and `mod13`. Entry/operation caps are explicit and failure falls back without excluding any candidate. The previous `auto` decomposition and `mini_bucket` bound remain available.

The factor lab exposes the remaining finite experiments and conditional queries. Ordinary coordinate assignments in this lab are not plaintexts. The normal optimizer reconstructs keys and literally re-encrypts retained cipher candidates. Examples: [junction optimization](../examples/optimize-Q-junction.json), [overlap bound](../examples/optimize-Q-overlap.json), and [conditional message reuse](../examples/factor-Q-conditional.json).

## Validation and comparisons

The fixed experiment has **33 controls and 17 integrated variants: 561 exact comparisons**, plus five search orderings, explicit relation complements, natural/bound-first value orderings, and separate mechanism controls. It includes seven structural cases, 24 seeded cases, and two real ciphertext/affine-family controls. The independent oracle uses literal table indexing and affine gram arithmetic. Top-k and zero-product lexical ties have separate tests. The new focused suite has **20 passing tests**, including actual two-process sharing, source-independent literal re-encryption, boundedness, partition scope, work-accounting regressions, and rejection of the unsuccessful portfolio option.

The comparison includes the previous release's exact `auto` decomposition, `mini_bucket`, and four-factor grouped bound. This matters: junction and strip methods **tie the previous exact decomposition on branch decisions in these 33 controls**. Their message/cache facilities are new; zero outer search nodes are not new evidence that exact decomposition was invented here.

Internal AND/OR and diagram branching counts are included. Single-factor full-objective table rows are counted separately. Complete heap combination scores, preprocessing, factor rows, strong probes, query replay, and shared-incumbent replay are recorded rather than hidden behind a smaller main search tree. A score of zero is feasible, including when it annihilates otherwise positive component scores.

## Every numbered outcome

“Retained alternative” means the bounded implementation passes exact-result tests and remains optional; it does **not** mean it beats the strongest previous strategy. “Supporting primitive” identifies measured reductions in representation/factor work without a separate primary-count win. The restart portfolio is rejected after a negative bounded comparison.

## Independent review fixes

The constraint author found that ordinary seed assignments could violate a requested search partition. Ordinary seeds now reject that mismatch; intentional shared global incumbents have explicit scope reporting. The model author found that the cutset planner could materialize a huge combination layer before checking its work cap. It now streams and charges each candidate before checking it. Both have regression tests.

Two accounting corrections were made after the hardware benchmark: heap-combination scores are now counted, and a rejection after the final factor is a complete evaluation. These change only factor-lab accounting, not the accelerated CPU/CUDA implementation used by that benchmark.
